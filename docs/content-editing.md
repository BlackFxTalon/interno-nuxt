# Редактирование контента через Decap CMS

Сайт остаётся статическим (SSG) на Timeweb. Decap CMS работает в браузере
по адресу `/admin/`, редактирует файлы репозитория и не требует Nuxt SSR
или отдельной базы данных.

## Что можно редактировать

| Раздел админки | Файлы |
|---|---|
| Матрасы, кровати, детские кровати, подушки, топперы | `content/products/<категория>/*.json` |
| Страницы «О нас», FAQ, возвраты, политика | `content/pages/*.md` |
| Меню в шапке | `content/navigation/header.json` |
| Главный баннер | `content/sections/hero.json` |

Формы описаны в `public/admin/config.yml`, схемы данных сайта — в `content.config.ts`.
При добавлении нового поля товара обновляйте оба файла. Тест `tests/decap.config.test.ts`
проверяет, что формы охватывают все поля существующего каталога.
Данные подборщика в `data/` не редактируются через CMS.

## Локальное редактирование без OAuth

1. Установите зависимости: `npm ci`.
2. В первом терминале запустите `npm run dev`.
3. Во втором терминале запустите `npm run cms:dev`.
4. Откройте именно `http://localhost:3000/admin/`.
5. Если отображается кнопка локального входа, нажмите её; GitHub не нужен.
6. Внесите изменения и сохраните. Proxy меняет локальные файлы без автоматических коммитов.
7. Проверьте сайт, `git diff`, выполните `npm run test:unit` и `npm run generate`.
8. Сделайте commit/push самостоятельно.

Локальный proxy привязан к `127.0.0.1:8081`, работает в filesystem-режиме
и разрешает браузерные запросы только с `http://localhost:3000`.
**Не запускайте его как production-сервис, не проксируйте его через Nginx
и не открывайте порт наружу:** в нём нет авторизации, а API может менять файлы.
`local_backend` активируется Decap только на локальном хосте; если proxy не запущен,
CMS может предложить обычный вход GitHub — для локальных файлов сначала запустите proxy.

## Однократная настройка production-входа

Админка и коллекции подготовлены, но production-авторизация ещё не подключена.
`backend.base_url` сейчас указывает на зарезервированный пример
`https://cms-auth.example.com` — это не работающий сервис.

### 1. Подключите OAuth-сервис

GitHub backend требует серверного обмена OAuth-кода на токен. Сервис можно
разместить отдельно на Timeweb (за Nginx) или на другом хостинге.
Используйте поддерживаемый Decap-совместимый OAuth proxy, а не локальный `decap-server`.
Варианты и инструкции: [External OAuth Clients](https://decapcms.org/docs/external-oauth-clients/).

У выбранного сервиса должны быть:

- HTTPS и endpoint начала авторизации, обычно `/auth`;
- callback, соответствующий его документации;
- проверка OAuth `state` и безопасный обмен сообщениями с админкой;
- разрешённый origin только вашего сайта, а не `*`;
- GitHub OAuth client ID и client secret в серверном окружении.

Создайте GitHub OAuth App и укажите callback URL из документации этого сервиса.
Секреты не добавляйте в `public/`, `content/`, Git или Nuxt public runtime config.
После выбора сервиса заполните **реальные** значения в `public/admin/config.yml`:

```yaml
backend:
  name: github
  repo: BlackFxTalon/interno-nuxt
  branch: main
  base_url: https://ВАШ-ДОМЕН-OAUTH-СЕРВИСА
  auth_endpoint: auth # путь вашего сервиса, без начального /
```

Это пример необходимых ключей: сохраните также уже настроенные `commit_messages`.
Настройте запрашиваемые GitHub-права по инструкции сервиса; для приватного
репозитория нужны соответствующие права доступа к репозиторию.

### 2. Дайте редактору доступ к GitHub

Редактор входит своей GitHub-учётной записью и должен иметь право push в репозиторий.
Это доступ к репозиторию, не только к отдельным полям CMS — выдавайте его доверенным людям.
Если `main` защищён обязательным PR, прямое сохранение в режиме `simple` будет
заблокировано: потребуется настроить editorial workflow и процесс вливания PR.
Текущая конфигурация рассчитана на прямые коммиты в `main`.

### 3. Опубликуйте сайт

Сделайте commit/push настроек. Существующий `.github/workflows/deploy.yml`
собирает сайт командой `npm run generate` и копирует `.output/public` на Timeweb.
`public/admin/` попадает в этот каталог автоматически.

Проверьте на опубликованном сайте:

1. `/admin/` открывается как отдельная админка, а не главная страница Nuxt.
2. `/admin/config.yml` и JS/CSS доступны без ошибок и устаревшего кэша.
3. Вход возвращает из GitHub в админку с доступом к нужному репозиторию.
4. После сохранения тестовой правки появляется commit в `main` и запускается deploy.
5. После успешного deploy правка видна на сайте.

Авторизация в production требует реального OAuth-сервиса и учётной записи;
локальные unit-тесты не заменяют эту проверку.

### Nginx на Timeweb

В существующем `server`-блоке с настроенным `root` можно использовать:

```nginx
location = /admin {
    return 301 /admin/;
}

location ^~ /admin/ {
    index index.html;
    try_files $uri $uri/ =404;
    add_header Cache-Control "no-cache" always;
    add_header X-Robots-Tag "noindex, nofollow" always;
}
```

Проверьте MIME-типы `.js`, `.css` и конфигурацию `index`.
Общий SPA fallback сайта не должен подменять `/admin/` или отсутствующие файлы админки.
PWA уже настроен не прекэшировать `/admin/*` и не использовать для него navigation fallback.

## Работа редактора на сайте

1. Откройте `/admin/`, войдите через GitHub.
2. Выберите категорию и товар либо страницу/настройку.
3. Измените текст, характеристики, цены или фотографии.
4. Сохраните/опубликуйте изменения — CMS создаст commit в `main`.
5. Дождитесь успешного GitHub Actions deploy: только после него меняется опубликованный сайт.

Фото можно выбрать из медиатеки, загрузить с компьютера или указать существующий URL.
Новые загрузки хранятся в `public/images/uploads` и доступны по `/images/uploads/...`.
Учитывайте размер фотографий: файлы в Git увеличивают размер репозитория и время деплоя.

## Правила каталога

- Один товар — один JSON-документ. Категория фиксируется выбранным разделом CMS.
- `slug` уникален во всём каталоге и задаёт `/product/{slug}`. Смена slug меняет ссылку;
  без редиректа прежняя ссылка перестанет работать. Перенос между категориями
  и переименование существующих файлов лучше выполнять разработчику через Git.
- В «Размеры» задавайте одинаковые код и название (например, `80×190`).
- В «Цены» и «Вес» добавляйте строки с теми же кодами размеров.
  Виджет сохраняет JSON-объекты, а не массивы; поддерживает десятичную запятую,
  проверяет пустые/повторяющиеся размеры и неотрицательные числа.
- Неизменённые значения цен и веса сохраняют исходный числовой/строковый тип.
- Дополнительные характеристики всех существующих товаров включены в формы.
- Проверьте ссылки на фото, alt-тексты и характеристики перед публикацией.
- Удаление документа удаляет товар после деплоя; отменить ошибку можно возвратом Git-коммита.

Ссылки на справку: [GitHub backend](https://decapcms.org/docs/github-backend/),
[локальный proxy](https://decapcms.org/docs/decap-proxy/).
