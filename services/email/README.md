# Отдельный Express-сервис форм

Это исходники существующего сервиса Timeweb, а **не Nuxt API**. Статический сайт отправляет POST `/api/send-email`; Nginx проксирует его на `127.0.0.1:3001`. По умолчанию требуется отдельное согласие текущей версии. Backend вынесен в репозиторий для тестов, контроля версии и повторяемого обслуживания; обычный GitHub deploy публикует сайт, но не переустанавливает Express автоматически.

## Проверки

```sh
npm ci --prefix services/email --ignore-scripts
npm run test:email
npm audit --prefix services/email --omit=dev
```

Тесты не загружают рабочий `.env`, не соединяются с SMTP/SmartCaptcha, не отправляют письма и используют временные файлы для проверки хранения. В VM-тесте возможна предупредительная строка Express о межконтекстном Promise; в обычном запуске обработчик использует native Promise.

## Сервер

- `/var/www/email-service`: исходники и зависимости, владелец root, каталог 750, группа `interno-mail`.
- `.env`: root:interno-mail 640; не копировать в Git, вывод команд или общедоступные артефакты.
- `server.cjs`: точка входа; привязка только к IPv4 loopback.
- `/var/lib/interno-email/consents`: минимальные подтверждения, каталог 700, файлы 600, владелец `interno-mail`; вне веб-каталога.
- `deploy/`: полный systemd unit, отдельный journald namespace и ежедневное удаление истёкших подтверждений. Требуется заранее созданный непривилегированный системный пользователь `interno-mail`.
- `GET /healthz`: внутренняя проверка доступности; не проверяет доставку почты.
- rate limit: 10 запросов за 15 минут на IP/IPv6-подсеть, только локальный Nginx считается доверенным прокси.

## Согласованный релиз

1. Подготовить закрытую резервную копию приложения, units и конфигурации. Не включать содержимое `.env` в вывод или локальный архив.
2. Собрать отдельный кандидат приложения, установить lock-зависимости через `npm ci --ignore-scripts`, выполнить тесты, сверить SHA-256 документа с опубликованной версией.
3. Установить код и systemd units с сохранением владельцев, разрешений и существующего SMTP/CAPTCHA `.env`. В кратком переходном режиме допустимы `CONSENT_REQUIRED=false` **и** будущий `CONSENT_LEGACY_UNTIL` (не более 30 минут). Без корректного срока режим закрыт; старым запросам не создаётся фиктивное подтверждение.
4. Опубликовать сайт с отдельным документом и чекбоксами, проверить страницу документа, формы, SW и соответствие версии API.
5. Удалить переходный override: в рабочем режиме `CONSENT_REQUIRED=true`. Перечитать units, перезапустить только Express, проверить liveness и timer. Старые открытые вкладки без согласия должны обновить страницу; принимать такие запросы молча нельзя.
6. При сбое вернуть согласованную предыдущую версию приложения/units, не теряя защиту файлов и непривилегированный запуск. Для изменения Node-зависимостей сначала проверить отдельный кандидат.

## Регламент оператора

См. [`docs/personal-data-operations.md`](../../docs/personal-data-operations.md). Серверное удаление подтверждения не удаляет заявку из почты. Сроки обычной заявки и обязательных договорных/бухгалтерских документов не взаимозаменяемы. Технические меры не являются юридической сертификацией.
